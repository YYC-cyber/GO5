# 卡牌对决游戏设计文档

## 项目定位

`卡牌对决` 是一款轻量级回合制卡牌战斗游戏。核心体验来自三件事：根据敌人意图规划出牌、围绕角色牌组形成不同打法、在分支关卡中通过奖励和路线选择调整推进方向。

当前版本的目标不是完整复刻商业 Roguelike 卡牌游戏，而是在较小代码规模内实现可玩、可扩展、便于调试的卡牌战斗框架。

## 设计目标

| 目标 | 当前实现 |
|---|---|
| 快速开始 | 运行 `python main.py` 后自动打开浏览器 |
| 角色差异 | 9 个角色拥有不同初始牌组和技能 |
| 策略决策 | 敌人意图提前显示，玩家可根据意图选择攻击、防御或叠状态 |
| 短局体验 | 经典模式提供单场战斗 |
| 长线体验 | 关卡模式提供 30 层分支路线、过关奖励、金币商店和路线选择 |
| 自定义验证 | 自定义模式可快速测试敌人组合 |
| 内容扩展 | 卡牌、角色、敌人都以类和配置表组织 |

## 游戏循环

一场战斗由玩家回合和敌人回合交替组成。

```text
战斗开始
  ↓
玩家回合开始：重置能量、重置技能使用状态、触发回合开始能力、抽牌
  ↓
敌人决定下一步意图并显示给玩家
  ↓
玩家出牌、使用技能、选择目标
  ↓
玩家结束回合：结算状态、弃掉手牌
  ↓
敌人按意图行动
  ↓
敌人结算状态
  ↓
判断胜负，未结束则进入下一回合
```

玩家可以在回合内打出多张卡牌，只要能量足够。能量界面显示为 `当前能量/最大能量`，例如 `6/3`；卡牌或技能获得的能量可以超过最大值。每个角色的技能每回合只能使用一次，下一回合开始时恢复。

## 模式设计

### 经典模式

经典模式用于快速战斗，不继承关卡进度，也不发放过关奖励。它适合测试角色牌组、验证敌人机制和快速体验战斗节奏。

| 模式 | 敌人 |
|---|---|
| 普通 | 哥布林、毒沼史莱姆 |
| 精英 | 熔岩犬、护卫队长 |
| Boss | 诅咒法师、镜像怪 |

### 关卡模式

关卡模式包含 30 层分支路线。每层 2-3 个节点可选，玩家根据自己的血量、牌组强度和金币选择最优路线。玩家通关后先选择奖励，再从多个下一关节点中选择路线，最终汇合到 Boss 关。玩家生命值、力量、能力类成长、牌组升级和删牌结果会在关卡之间保留。负面状态、手牌、格挡和能量会在过关后清理。

领奖后会进入独立路线选择界面。该界面会标记已走节点、当前节点和可选分支；玩家选完路线后回到战斗页面，并进入对应关卡。

| 路线类型 | 风险 | 奖励倾向 | 是否有战斗 | 设计意图 |
|---|---|---|---|---|
| 普通战 | 中 | 普通升级、基础成长 | 是 | 标准战斗节点，提供稳定推进节奏 |
| 精英 | 高 | 遗物、高概率升级、稀有强化 | 是 | 牌组强势时用更高战斗压力换更强成长 |
| 事件 | 中 | 随机回血、失血换奖励、获得诅咒 | 否 | 弹窗反馈随机结果，提供不确定性 |
| 营火 | 低 | 恢复、净化、删牌 | 否 | 弹窗反馈休整结果，玩家主动整理牌组 |
| 商店 | 低 | 金币交易、购牌、回血 | 否 | 使用金币购买物品，在中段随机出现 |
| Boss | 最高 | 通关胜利 | 是 | 所有路线最终汇合的决战节点 |

事件、营火和商店为非战斗节点，进入后触发弹窗界面显示结果。商店节点可以用金币购买物品，事件节点触发随机效果，营火节点净化状态并回复生命。Boss 前（第 29 层）固定为营火节点。

#### 金币系统

战斗结束后根据难度和层数奖励金币。金币显示在角色 HP 旁边。

| 难度 | 金币范围 |
|---|---|
| 简单 | 5-10 |
| 困难 | 8-14 |
| 地狱 | 12-18 |

层数每增加 5 层，金币 +1。

#### 商店系统

商店节点随机出现在层 5-20 之间，共 4-6 个。商店界面全屏覆盖，显示当前金币和可用商品。

| 商品 | 价格 | 效果 |
|---|---|---|
| 生命恢复 | 15💰 | 回复 25 HP |
| 完全恢复 | 30💰 | HP 回满 |
| 力量药水 | 12💰 | 下一轮攻击 +3 |
| 护盾药水 | 10💰 | 下一轮防御 +8 |
| 删牌 | 20💰 | 随机删除一张牌 |
| 升级卡牌 | 18💰 | 随机升级一张牌 |
| 体魄强化 | 22💰 | 最大生命 +10 |
| 能量核心 | 35💰 | 最大能量 +1 |
| 随机遗物 | 40💰 | 获得一个随机遗物 |

购买后即时生效，商品消失。离开商店后进入路线选择。

#### 过关奖励

过关奖励包含：

| 奖励 | 效果 |
|---|---|
| 回复生命 | 回复 20 点生命 |
| 稀有强化 | 力量 +1，最大生命 +5 |
| 最大生命 | 最大生命 +8，并回复 8 点生命 |
| 完全恢复 | 回复至满血，每局只能出现并使用一次 |
| 特殊强化 | 最大能量 +1 |
| 下一轮攻击 | 下一场战斗伤害 +3 |
| 下一轮防御 | 下一场战斗开始获得 8 格挡 |
| 补给休整 | 净化负面状态并回复 18 点生命 |
| 升级卡牌 | 随机提供一张未升级卡牌作为升级选项 |
| 删除卡牌 | 从当前牌组中删除一张牌 |
| 遗物 | 获得一个简单被动效果 |

当前版本不再提供"过关获得新卡"的奖励。这样关卡成长更偏向强化、精简和生存，而不是不断膨胀牌组。

### 遗物系统

遗物是关卡模式的被动成长，主要由精英、事件和营火节点提供。当前版本包含 10 个简单遗物，效果覆盖战斗开始获得格挡、力量、能量、祝福、骷髅、回响、治疗，或对敌人施加中毒和烧伤。

遗物在每场战斗开始时自动生效，战斗结束后临时 buff 清空，下次战斗开始时遗物重新生效。

### 自定义模式

自定义模式用于自由配置敌人。玩家可以选择角色，设置玩家生命值，添加 1 到 5 名敌人，并调整敌人的生命和攻击力。

## 角色设计

### 角色定位

| 角色 | 生命 | 核心打法 | 技能 |
|---|---:|---|---|
| 勇者 | 80 | 平衡攻防，力量成长 | 净化 |
| 精灵 | 65 | 多段攻击、连击、抽牌 | 回响 |
| 巫师 | 55 | 中毒、烧伤、状态爆发 | 元素爆发 |
| 圣骑士 | 90 | 格挡保留、护盾转伤害 | 圣盾 |
| 刺客 | 60 | 流血、低费、弃牌爆发 | 暗影爆发 |
| 牧师 | 75 | 治疗、净化、祝福、反伤 | 神圣新星 |
| 机械师 | 70 | 炮台、电池、模块成长 | 超频 |
| 亡灵法师 | 58 | 生命换资源、骷髅、诅咒 | 亡者复苏 |
| 炼金术士 | 68 | 中毒、随机强化、状态转换 | 万能药剂 |

### 技能规则

角色技能消耗能量，且每回合只能使用一次。技能是否可用由以下条件共同决定：

- 当前战斗未结束
- 当前能量大于等于技能消耗
- 本回合尚未使用过技能

圣骑士的技能是被动技能，表现为每回合自动获得护盾且格挡可保留。前端不会显示可点击主动技能按钮。

## 卡牌设计

### 卡牌分类

| 类型 | 作用 |
|---|---|
| 攻击 | 对敌人造成伤害，通常受力量影响 |
| 技能 | 提供格挡、治疗、抽牌、能量或状态效果 |
| 能力 | 提供持续效果，例如铁壁、祝福、炮台、骷髅 |

### 目标规则

攻击牌和敌方状态牌通常需要选择敌人。自身目标牌会自动作用于玩家，不需要选择目标。

自身目标牌包括防御、治疗、能力、抽牌、能量、召唤、模块成长等类型。

### 升级规则

卡牌升级会改变实际数值，而不仅是描述文本。升级可能影响：

- 伤害
- 格挡
- 治疗量
- 抽牌数
- 能量获得
- 状态层数
- 持续能力数值

## 状态设计

| 状态 | 持有者 | 结算规则 |
|---|---|---|
| 力量 | 玩家/敌人 | 提高攻击伤害 |
| 格挡 | 玩家/敌人 | 抵消伤害，默认回合结束清空 |
| 中毒 | 玩家/敌人 | 回合结束受到层数伤害，层数 -1 |
| 烧伤 | 玩家/敌人 | 回合结束受到层数伤害，层数 -1 |
| 流血 | 玩家/敌人 | 回合结束受到层数伤害，层数 -1 |
| 虚弱 | 玩家/敌人 | 降低攻击伤害，回合结束层数 -1 |
| 易伤 | 玩家/敌人 | 受到伤害增加，回合结束层数 -1 |
| 诅咒 | 玩家/敌人 | 受到伤害时额外受到诅咒层数伤害，回合结束层数 -1 |
| 祝福 | 玩家 | 每回合开始获得格挡 |
| 反伤 | 玩家 | 被敌人攻击时反击伤害 |
| 炮台 | 玩家 | 每回合开始自动攻击首个存活敌人 |
| 骷髅 | 玩家 | 每回合开始自动攻击首个存活敌人 |

## 敌人设计

### 基础敌人

哥布林、史莱姆、火焰领主、寒冰法师和暗影领主使用通用意图逻辑：攻击、防御和强化。低血量时更倾向防御，力量较高时更倾向攻击。

### 机制敌人

| 敌人 | 特殊意图 | 效果 |
|---|---|---|
| 毒沼史莱姆 | 毒液 | 造成少量伤害并施加中毒 |
| 熔岩犬 | 灼咬 | 攻击并施加烧伤 |
| 镜像怪 | 镜像 | 模仿玩家上一张牌的气势，造成伤害并施加易伤 |
| 护卫队长 | 守护 | 为全体敌人提供格挡 |
| 诅咒法师 | 诅咒 | 往玩家弃牌堆加入诅咒牌，并施加诅咒 |

敌人意图在玩家回合开始时确定并展示。敌人行动时不会重新随机意图，这样玩家的决策信息是可信的。

前端会展示详细意图文案，例如"毒液：3伤害 + 2中毒""守护：全体+10格挡"。状态图标支持鼠标悬停说明，降低复杂状态的理解成本。

## 前端界面

页面结构由 `static/index.html` 定义，主要区域包括：

- 关卡进度条和路线图
- 敌人区域
- 战斗日志
- 手牌区域
- 奖励面板
- 玩家状态栏（含金币显示）
- 角色与模式选择弹窗
- 快捷键帮助弹窗
- 牌堆详情弹窗
- 独立路线选择界面
- 商店界面（商店节点）
- 事件/营火弹窗（非战斗节点）
- 状态和遗物 tooltip
- 受击、格挡、技能、状态伤害的轻量动画反馈

前端逻辑由 `static/js/game.js` 负责，包括 API 请求、状态渲染、出牌交互、快捷键、目标选择、自定义敌人配置、奖励领取、商店购买和事件弹窗。

样式由 `static/css/style.css` 负责，使用暗黑主题、卡牌类型颜色、敌人意图标签、状态标签和响应式布局。

## 后端结构

| 文件 | 职责 |
|---|---|
| `main.py` | 启动入口，清理旧端口并启动 Flask 服务 |

| `src/core/character.py` | 玩家和敌人的基础属性、伤害、治疗、状态结算 |
| `src/core/player.py` | 玩家类、角色模板、抽牌、出牌、回合开始/结束 |
| `src/core/enemy.py` | 敌人类、意图选择、敌人行动、详细意图文案 |
| `src/core/card.py` | 所有卡牌类和卡牌效果 |
| `src/games/web_battle.py` | Web 战斗控制器，负责战斗流程和状态序列化 |
| `src/games/level_mode.py` | 关卡模式、30 层分支路线图、金币商店、奖励系统、遗物系统 |

## API 设计

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/` | 返回游戏页面 |
| `GET` | `/api/game-state` | 获取当前游戏状态 |
| `POST` | `/api/new-game` | 开始经典模式 |
| `POST` | `/api/start-level` | 开始关卡模式 |
| `POST` | `/api/start-custom` | 开始自定义模式 |
| `POST` | `/api/play-card` | 打出一张牌 |
| `POST` | `/api/end-turn` | 结束玩家回合 |
| `POST` | `/api/use-skill` | 使用角色技能 |
| `POST` | `/api/claim-reward` | 领取关卡奖励 |
| `POST` | `/api/choose-branch` | 选择下一关分支路线 |
| `POST` | `/api/open-shop` | 打开商店（商店节点） |
| `POST` | `/api/buy-item` | 购买商店物品 |
| `POST` | `/api/leave-shop` | 离开商店，进入路线选择 |

战斗状态通过 JSON 返回。前端不直接计算规则，只负责展示后端返回的状态。

## 资源设计

角色和敌人头像统一放在 `static/images`。当前头像使用 SVG 格式，命名与角色或敌人中文名一致，例如：

```text
勇者.svg
刺客.svg
毒沼史莱姆.svg
诅咒法师.svg
```

`WebBattle.CHARACTER_IMAGES` 负责把角色/敌人名称映射到头像文件名。

## 测试策略

当前测试以基础流程验证为主：

```bash
python -m compileall src tests
python tests/test_battle.py
node --check static/js/game.js
```

推荐后续补充以下测试：

- 每个角色都能正常开局
- 每个技能一回合只能使用一次
- 每个敌人的特殊意图都能执行
- 卡牌升级后的数值与描述一致
- 关卡奖励不会生成"新增卡牌"选项
- 自定义模式的敌人攻击力配置能生效
- 商店购买后金币正确扣除
- 非战斗节点弹窗正确显示
- 离开商店后能进入路线选择

## 扩展约定

新增卡牌时，在 `src/core/card.py` 新增类，并继承 `Card`。如果卡牌作用于玩家自身，需要把中文牌名加入 `WebBattle.SELF_TARGET_NAMES`。

新增角色时，在 `CHARACTER_TEMPLATES` 中添加角色配置，并在前端角色选择区域添加对应选项。

新增敌人时，优先在 `Enemy.choose_intent()` 和 `Enemy.take_turn()` 中补充特殊意图。如果敌人需要出现在关卡模式，还需要更新 `level_mode.py` 的关卡配置；如果需要出现在自定义模式，还需要更新前端 `ET` 敌人列表。

新增头像时，把 SVG 放入 `static/images`，并更新 `WebBattle.CHARACTER_IMAGES`。
